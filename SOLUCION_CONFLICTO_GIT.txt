║   🔧 SOLUCIÓN RÁPIDA - CONFLICTO DE GIT EN PRODUCCIÓN       ║

El problema es que archivos de storage/ (caché y logs) están en Git
cuando NO deberían estarlo. Aquí está la solución:

┌───────────────────────────────────────────────────────────────┐
│ OPCIÓN 1: SOLUCIÓN RÁPIDA (RECOMENDADA)                     │
└───────────────────────────────────────────────────────────────┘

Copia y pega estos comandos UNO POR UNO en tu servidor:

# 1. Cancelar el merge conflictivo
git merge --abort

# 2. Hacer backup de storage (por seguridad)
cp -r storage storage_backup_$(date +%Y%m%d_%H%M%S)

# 3. Eliminar archivos problemáticos
rm -rf storage/framework/cache/data/*
rm -f storage/logs/*.log

# 4. Guardar cambios locales
git stash

# 5. Pull limpio
git pull origin main

# 6. Limpiar caché de Laravel
php artisan cache:clear
php artisan view:clear
php artisan config:clear
php artisan route:clear

# 7. Configurar permisos
chmod -R 775 storage bootstrap/cache

# 8. Cachear para producción
php artisan config:cache
php artisan route:cache
php artisan view:cache

# 9. Verificar que funcione
curl -I https://audaz.site/

┌───────────────────────────────────────────────────────────────┐
│ OPCIÓN 2: FORZAR PULL (SI LA OPCIÓN 1 NO FUNCIONA)          │
└───────────────────────────────────────────────────────────────┘

# ⚠️ CUIDADO: Esto descarta TODOS los cambios locales

# 1. Hacer backup
cp -r storage storage_backup_$(date +%Y%m%d_%H%M%S)

# 2. Resetear a la versión remota
git fetch origin
git reset --hard origin/main

# 3. Limpiar archivos no rastreados
git clean -fd

# 4. Limpiar caché
php artisan optimize:clear

# 5. Cachear para producción
php artisan config:cache
php artisan route:cache
php artisan view:cache

# 6. Permisos
chmod -R 775 storage bootstrap/cache

┌───────────────────────────────────────────────────────────────┐
│ OPCIÓN 3: SOLUCIÓN DEFINITIVA (PREVENIR FUTUROS CONFLICTOS) │
└───────────────────────────────────────────────────────────────┘

Después de resolver el conflicto, ejecuta esto en tu MÁQUINA LOCAL:

# 1. Asegurarse de que storage/ esté en .gitignore
cat >> .gitignore << 'EOF'

# Storage files (no versionar)
storage/framework/cache/data/*
storage/logs/*.log
storage/debugbar/*
EOF

# 2. Eliminar archivos de storage del repositorio
git rm -r --cached storage/framework/cache/data/
git rm --cached storage/logs/*.log

# 3. Commit y push
git add .gitignore
git commit -m "fix: Remove storage files from git tracking"
git push origin main

┌───────────────────────────────────────────────────────────────┐
│ ¿POR QUÉ PASÓ ESTO?                                          │
└───────────────────────────────────────────────────────────────┘

Los archivos de storage/ (caché y logs) son archivos temporales
que cada servidor genera. NO deben estar en Git porque:

1. Son diferentes en cada ambiente
2. Cambian constantemente
3. Causan conflictos en cada pull
4. Ocupan espacio innecesario en el repo

La solución definitiva es eliminarlos del repo (Opción 3).
